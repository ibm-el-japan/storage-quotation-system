## 1. 目的
IBM Expert Labs Japan（ストレージ）の見積業務を自動化する。
`見積もり依頼記入シート(Excel)` → `概算見積シート` → `S-LINK / 仕様書・別紙` と、別メニューの `CPS入力`。UI・出力は日本語。

## 2. 画面と役割
| ページ | 役割 |
|---|---|
| `index.html` | ポータル。依頼シート(xlsx)を解析して各ページへ |
| `request-form.html` | 依頼記入シートの入力フォーム(6ステップ) |
| `quotation-generator.html` | 概算見積(工数・出張費・チェックリスト・取込状況パネル) |
| `slink-spec-generator.html` | S-LINK 24項目、仕様書、別紙 |
| `cps-input.html` | CPS(Cost Plan Sheet)入力。別メニュー(R8) |

`parseQuotationRequestExcel` は index / request-form / quotation-generator / slink-spec-generator の **4ページで同一実装**。変更時は4箇所を同期する。

## 3. 守るべき制約 (会議メモ R1–R11)
- R1 値の取得元を表示する（Phase3 で文字色にも拡張）。
- R3 チェックされていない項目は出力しない。
- R4 サービス内容に「設計/構築/稼動テスト/ドキュメント/Q&A」だけの定型行を紛れ込ませない。
- R5 取り込んだデータは EL SE が確認する（「確認済み」チェック）。
- R8 CPS は別メニュー。
- R9 既存ドキュメントの書式に合わせる。
- R10 支払い計画はツールで確定しない。既定値はツール算出・編集可・「要営業確認」。
- R11 項目ごとにテストし、Slack 用サマリーを出す。
- お客様向け出力（見積書・仕様書・別紙・チェックリスト出力・S-LINKコピー値）に色やバッジを入れない。

## 5. Phase3 (v2.5.0) の要点
**ユーザー要件**: (1) テンプレートのグレー文字は参考情報で、実案件では黒字。(2) テンプレート全情報を漏れなく反映。(3) 取り込んだ値が依頼シート由来だと一目で分かる（例: 赤字）。(4) 依頼シート由来とシステム決定・補完値を別の文字色で区別。

**色の判定** (`readSheetColors`): `XLSX.read(data, {type:'array', cellStyles:true, bookFiles:true})` で残る生XML（styles / sharedStrings / sheet）を突合。セル単位とリッチテキストrun単位で判定。
グレー = theme 0/2 ＋ 負のtint、または無彩色 #70–#DD。色情報が取れない場合は `colorDetect:false` で全値を依頼シート扱い。

| 取得元 `origin` | 意味 | 文字色 | バッジ |
|---|---|---|---|
| `sheet` | 依頼シートの黒字（実入力） | 赤 #c00000 | 依頼シート |
| `reference` | 依頼シートのグレー（参考記入例） | グレー斜体 #8b8f98 | 参考例（グレー） |
| `default` | システムが決定・補完 | 青 #1d4ed8 | システム補完 |
| `manual` | 取込後に手入力・編集 | 黒 | 手入力 |
| `empty` | 記載なし（推測しない） | — | 未入力 |

**テンプレートの色の実態**: 行4–51 はグレー。事前確認事項(Y/N)と契約情報(行72–88)は黒。したがってテンプレートをそのまま取り込むと、案件情報は「参考例」、契約情報は実入力扱いになる。

**修正した不具合**: 記入日「20xx/xx/xx」の本日付置換／契約形態の「（例）…」混入／提供場所(地名・駅名)のリモート誤判定／request-form だけ緩かった打合せ判定／「サービス内容」と「サービス内容（詳細）」の混同。

## 9. GitHub 連携と管理者パスワード (v2.5.3)
- アプリ本体（公開）: `ibm-el-japan/storage-quotation-system`（GitHub Pages）。顧客データ・CPS 単価表（xlsm）は置かない。
- 案件ファイル（非公開）: `ibmkevin/storage-quotation-work` の `work/`。ツールの「保存 → GitHubへ」「GitHubから開く」「API保存」はここだけを使う。PAT は `repo` スコープ、リポジトリへの招待が必要。
- 非公開リポジトリのため、PAT なしでは一覧取得できない（取得時に入力を促す）。
- 管理者パスワードは `quotation-generator.html` に **ハッシュのみ** 保持（`ADMIN_PW_SALT` + `ADMIN_PW_SHA256`）。平文は置かない。
  - 変更手順: `python3 -c "import hashlib;print(hashlib.sha256(('sqs-admin-v1:'+'新パスワード').encode()).hexdigest())"` の出力を `ADMIN_PW_SHA256` に設定。
  - これは画面の出し分け用。実際のアクセス制御は GitHub の権限と PAT。ハッシュは公開されるため、強い（長いランダムな）パスワードにする。
  - 新パスワードはユーザーに別途伝達済み。リポジトリやドキュメントには記載しない。
- 旧 `work/`（公開リポジトリ）には案件ファイルが無いことを確認済み（README のみ）。
