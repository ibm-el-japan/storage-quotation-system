1. HTML化するメリット（5大導入価値）

従来のExcelベースの手作業による見積もり作成フローを、ブラウザ完結のHTMLツール群へ移行することで得られる主要なメリットは以下の5点です。

評価軸 現行Excel運用の課題 HTML化による改善・導入メリット
① 二重入力・転記の完全排除 営業の依頼書、概算見積、仕様書Word、別紙、CPS（CostPlanSheet）のそれぞれへ、案件名・顧客名・工数・金額を手動でコピペ・再入力。 Single Source 一括自動連携
営業の「見積もり依頼記入シート（.xlsx）」を1回ドラッグ＆ドロップするだけで全項目を自動解析し、後続の全ツール・全成果物へシームレスに自動展開（再入力ゼロ）。
② 100% OS非依存（Mac/Win共通） Windows専用マクロ(VBA)に依存。Mac環境で開くとマクロエラーやレイアウト崩れ・フォント乱れが発生し、手動修正を余儀なくされていた。 Mac / Windows 完全共通動作
Chrome、Safari、Edge 等の標準ブラウザのみで同一に動作。OSやExcelバージョンに左右されず、常に同一の計算結果と正規成果物を生成。
③ UIの堅牢性・操作性 Excel上で行の追加・削除や改行を行うと、行高の崩れ、数式の参照ズレ、チェックボックスの重なり・ズレが頻発。 堅牢なWeb UI操作
「＋」「✕」ボタンによる直感的な行操作、動的な自動再計算、自動折り返しが崩れることなく安定動作。
④ 出張費・手当の自動計算 訪問先ごとの距離区分（短/中/遠）、運賃調査、宿泊費計算、宿泊手当・帰着日手当の算出を手作業で行っており、計算ミスや確認負荷が大。 出張費アシスタントの自動算定
主要10都市プリセット（新幹線/航空便・運賃・宿泊費目安連動）、宿泊出張手当＋帰着日長距離手当(¥3,500)、予備率20%を自動試算・明細反映。
⑤ 提出用資料のクリーン出力 社内用のメモ、計算用セル、Provenanceバッジ等を誤って顧客に見せないよう、手作業で別ファイルに整形・コピー。 クリーン出力の自動生成
ワンクリックで社内用表示を排除した「前提シート」「見積もりシート」の公式2シート構成（PDF / Excel）を即時生成。

2. 現行Excel「コストプランシート（.xlsm）」との違い

「コストプランシート_お客様名_案件名_20260116.xlsm」等の現行Excelと、本システム（Storage Quotation System）の位置づけ・機能の違いを整理します。

📌 業務プロセスのカバー範囲の違い
現行Excel (CPS): 社内原価計算・GP承認・支払計画登録のみを担う「最終承認シート」
本HTMLシステム: 依頼受付 ➔ 概算見積試算 ➔ 顧客提出用見積書 ➔ 仕様書/別紙 ➔ CPS自動書込み までを繋ぐ「統合パイプライン」
比較項目 現行Excel（コストプランシート .xlsm） 本HTMLシステム（Storage Quotation System）
システムの役割 社内原価計算・GP%承認・支払計画登録のための「最終承認用シート」。 依頼受付から見積試算、顧客提出書、契約仕様書、CPS出力までを繋ぐ「統合パイプライン」。
依頼要件の取込 なし（依頼メールやExcelから目視で手動転記）。 原本Excelを直接解析し、顧客情報・対象製品・作業要件を自動展開。
工数・単価の管理 セルに手入力。年度別Band単価（B6〜B10）は別シートを参照して手計算。 年度別Band単価プリセット内蔵。月別工数（h）を入力するだけでLaborコストを自動計算。
顧客向け見積書の作成 別途見積書フォーマット（Excel/Word）を作成して転記。 標準3列形式（前提＋見積もり）のPDF / Excel をワンクリック自動生成。
契約仕様書・S-LINK 別途Wordファイルを開いて手動起票。S-LINK画面へ手動入力。 S-LINKメタデータ24項目一括コピー、Word（.doc）仕様書・別紙 を自動生成。
CPSへの反映 全項目を最初から手作業で入力・検算。 全入力データを埋め込んだ 記入済みCPS（.xlsm 2年版/3年版）を直接ダウンロード出力。

3. ツールの前提条件

💻 1. ユーザー実行環境
・HTML5 / ECMAScript 2020 対応のモダンブラウザ（Chrome, Edge, Safari）。
・PCローカル環境または GitHub Pages から直接アクセス。
・専用アプリやNode.jsのインストールは不要（100%クライアント完結）。
📑 2. 入出力の標準フォーマット
・入力: IBM Storage Expert Labs Japan 標準「見積もり依頼記入シート（.xlsx）」。
・出力: 公式CPS雛形（（2年_26-27）CostPlanSheetINF2026v1.1.xlsm / （3年_26-28）CostPlanSheetINF2026v1.1.xlsm）。
📈 3. 計算基準・社内単価テーブル
・IBM Expert Labs 標準の年度別Band単価（2025〜2028年 Band 6〜10）。
・Contingency率（標準10%）、Gross Profit率（標準40%）。
🚄 4. 出張・旅費の規程ルール
・出張判定図に基づく距離区分定義（短距離: 日帰り圏、中距離: 赤線、遠距離: 青線/範囲外）。
・宿泊費（2名往復運賃×1.3 を5,000円切上げ）、手当（中距離¥1,500、遠距離日帰り¥3,500、宿泊手当¥4,000、帰着日手当¥3,500）。

4. データ保存方式とセキュリティアーキテクチャ

本システムは、「顧客機微情報を外部サーバーに一切送信しない」 完全クライアントサイド設計を採用しています。

🔒 セキュリティ原則
・すべてのExcel解析（SheetJS）やExcel書き込み（JSZip）はブラウザ内メモリで完結し、外部クラウド・サーバーへのAPI通信は一切ありません。
・顧客名、Opportunity No、案件金額などの個別データは公開リポジトリへコミットされません。
保存・連携方式 仕組みとライフサイクル 利用シーンとメリット
① sessionStorage
（画面間一時連携）		 ブラウザのセッション領域に一時保管。タブを閉じるとメモリから即時破棄。 ポータル ➔ 概算見積 ➔ 仕様書 ➔ CPS入力 の画面遷移時にシームレスにデータを自動引継ぎ。共有PCでも安全。
② 案件JSON入出力
（構造化データ保存）		 全入力値・工数・条件を構造化された .json ファイルとしてローカル保存。 「保存」ボタンでPCに保管し、「開く」でいつでも再編集・過去案件の流用が可能。
③ スタンドアロン案件HTML
（自己完結型ファイル）		 共通パーサおよび案件データをHTML内部にインライン埋め込みして出力。 オフライン環境やメール添付でも、ダブルクリックだけで案件データ入りのツール画面が起動。

5. GitHubを利用する理由と管理方法

サーバーレス運用、厳密な版数管理、およびセキュリティ保護を両立するため、GitHubを活用しリポジトリの分離運用を行っています。

なぜGitHubを利用するのか

  • サーバー管理コストゼロ（GitHub Pages）: サーバー構築やミドルウェア保守なしで、チーム全員が常に最新版のWebツール（URL）にアクセス可能。
  • 厳密な版数管理と品質担保: 計算ロジックやUIの変更履歴がコミットログとして記録され、「誰が・いつ・何を変更したか」を完全に追跡可能。自動リグレッションテスト（tools/check.sh）でデグレを防止。
  • 組織内の共通ナレッジ化: ローカルに分散しがちなExcelマクロと異なり、コードとドキュメントが一元管理され、属人化を防止。
